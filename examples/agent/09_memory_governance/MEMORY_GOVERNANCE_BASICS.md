# 记忆治理基础知识

## 1. 为什么有了记忆还不够

上一模块学习了长期记忆的基础闭环：

```text
提取 -> 保存 -> 检索 -> 复用
```

但真实项目不能只做到这里。

长期记忆一旦保存，就可能在未来很多次回答中影响 Agent。如果记错了、过期了、包含敏感信息，后果会持续放大。

所以真实项目还需要治理能力：

```text
能看见
能修正
能删除
会过期
会拒绝敏感信息
能追踪每次变化
```

## 2. 用户必须能查看记忆

如果 Agent 记住了用户偏好，但用户完全看不到，就会出现两个问题：

- 用户不知道 Agent 为什么这样回答。
- 用户无法发现和修正错误记忆。

因此真实产品通常会提供“记忆管理”页面或接口，让用户看到类似内容：

```json
{
  "memory_type": "instruction",
  "key": "reply_language",
  "value": "中文",
  "status": "active",
  "expires_at": null
}
```

本模块用：

```text
GET /users/{user_id}/memories
```

来演示这个能力。

## 3. 删除记忆为什么通常先做软删除

删除有两种：

```text
物理删除：直接从数据库删掉。
软删除：记录还在，但 status = deleted，不再参与检索和回答。
```

教学模块使用软删除。

原因：

- 可以证明这条记忆确实被用户删除过。
- 可以排查“删除后为什么还影响回答”这种问题。
- 可以做审计日志，记录删除时间和删除原因。

但要注意：软删除不等于合规删除。真实项目如果用户要求彻底删除个人数据，可能还需要清理数据库、缓存、日志、备份中的数据。这个模块先讲工程链路，不展开合规细节。

## 4. 过期记忆为什么重要

有些记忆长期稳定：

```text
用户希望默认用中文回答。
```

有些记忆只在一段时间内有价值：

```text
用户正在学习 RAG。
用户最近在做一个 Agent 项目。
用户当前使用 FastAPI。
```

如果一年后还拿“正在学习 RAG”影响回答，可能已经不准确。

所以记忆可以有 `expires_at`：

```json
{
  "key": "current_topic",
  "value": "RAG",
  "expires_at": "2026-11-03T12:00:00"
}
```

检索时必须排除已过期记忆。

本模块里：

- `search_memories()` 会自动排除 expired。
- `/memory/expire-scan` 模拟定时任务，把到期记忆标记为 `expired`。

## 5. 敏感信息不能先存再删

真实项目里，敏感信息过滤必须发生在入库之前。

错误做法：

```text
先把用户输入存入长期记忆
-> 后面再定期清理敏感信息
```

问题是：数据一旦进入数据库，就可能进入日志、备份、缓存、分析系统。

正确做法：

```text
候选记忆
-> 敏感信息检测
-> 拒绝高风险内容
-> 只有安全内容进入 user_memories
```

本模块拒绝这些类型：

- API Key
- 密码
- 身份证号
- 银行卡号或长数字凭证
- 验证码

例如：

```text
我的密码是 abc123，以后请用中文回答。
```

教学版会拒绝由这段原文产生的候选记忆。

## 6. 为什么拒绝也要记录

拒绝保存敏感信息后，是否完全不留痕迹？

真实项目要平衡两个目标：

- 不能把敏感值写入长期记忆。
- 又要知道系统确实做过拒绝动作。

本模块使用 `MemoryAuditLog` 记录：

```json
{
  "action": "rejected",
  "reason": "疑似密码，不能写入长期记忆。",
  "after_json": {"risk_type": "password"}
}
```

注意：审计日志里也要避免保存完整敏感值。教学模块为了接口清晰，返回结构里会展示 `source_text`；生产环境需要进一步脱敏。

## 7. 更新记忆解决什么问题

长期记忆不是永远正确。

用户可能改变偏好：

```text
以前：以后请用中文回答。
现在：以后请用英文回答。
```

系统应该更新：

```text
reply_language = 英文
```

而不是同时保留中文和英文。

用户也可能发现 Agent 记错了：

```text
你记错了，我不是前端，我是后端。
```

这时需要提供手动更新接口。

本模块用：

```text
PATCH /users/{user_id}/memories/{memory_id}
```

来演示。

## 8. 审计日志的价值

审计日志记录记忆发生过什么变化：

- `created`
- `updated`
- `deleted`
- `expired`
- `used`
- `rejected`

这对后续模块很重要：

- 可观测性：为什么 Agent 这样回答？
- 安全：敏感信息有没有被拒绝？
- 评测：某次效果变化是否由记忆变化导致？
- 用户体验：用户删除后为什么不再个性化？

## 9. 本模块的限制

本模块为了教学清晰，保留了一些限制：

- 敏感信息检测是规则版，不是完整 DLP 系统。
- 没有真实登录鉴权，只用 `user_id` 演示隔离。
- 没有后台定时任务，只用 `/memory/expire-scan` 模拟。
- 没有物理删除和备份清理。
- 没有组织级、项目级、团队级 memory namespace。

这些能力会在后续工具权限、安全、生产部署模块继续扩展。
