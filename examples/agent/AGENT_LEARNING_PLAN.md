# Agent 正式学习路线

这份文档是 Agent 专项详细路线。

根目录 `LEARNING_PLAN.md` 负责整个项目的总路线；本文件负责把 Agent 方向展开到足够细，避免根目录路线变得过长。

目标不是“知道几个 Agent 名词”，而是学完后能独立开发、部署、评测、排查一个真实可用的 AI Agent 应用。

## 前置基础

进入这条路线前，应该已经完成：

- FastAPI 接口
- DeepSeek / mock 模型调用
- 聊天历史
- SQLAlchemy / PostgreSQL
- RAG 入门
- 后台任务
- 流式输出
- 认证、限流、日志
- Docker 部署
- Go AI 网关

这些不是 Agent 本身，但都是 Agent 会复用的工程地基。

## 第一部分：Agent 核心机制

### 00：什么是 Agent

对应模块：

- `examples/agent/00_what_is_agent`

目标：

- 理解普通聊天和 Agent 的区别。
- 理解目标、思考、动作、观察、最终回答。
- 理解 Agent 不等于大模型，也不等于工具调用。

要做的代码：

- 普通聊天接口 `/chat/basic`。
- 最小 Agent 接口 `/agent/run`。
- 返回 `steps`，展示 Agent 的中间步骤。

验收标准：

- 能用自己的话解释 Agent。
- 能通过 `/chat/basic` 和 `/agent/run` 对比两种流程。
- 能看懂 `goal -> think -> act_and_observe -> final_answer`。

### 01：工具调用

对应模块：

- `examples/agent/01_tool_calling`

目标：

- 理解工具 schema。
- 理解模型如何选择工具。
- 理解工具参数从哪里来。
- 理解后端为什么必须做工具白名单和参数校验。

要做的代码：

- `/tools` 查看工具清单。
- `/tool/run` 手动执行工具。
- `/chat` 根据用户问题触发工具。
- 支持 mock 模式和真实模型模式。

验收标准：

- 能新增一个工具。
- 能让 `/chat` 根据用户问题触发工具。
- 能处理工具参数错误和工具执行失败。

### 02：最小 Agent 循环

对应模块：

- `examples/agent/02_minimal_agent_loop`

目标：

- 理解 Agent 的核心循环。
- 理解 `思考 -> 动作 -> 观察 -> 下一步`。
- 用最大步数防止无限循环。

要做的代码：

- 一个最多执行 `max_steps` 次的 Agent。
- 每一步写入 `steps`。
- 支持工具成功、失败、继续和停止。

验收标准：

- 能解释为什么 Agent 循环不能无限执行。
- 能看懂每一轮 observation 如何影响下一步。
- 能让 Agent 在工具失败后选择停止或换一种方式回答。

### 03：多工具编排

对应模块：

- `examples/agent/03_multi_tool_orchestration`

目标：

- 理解一个目标可能需要多个工具协作。
- 理解工具之间的数据传递。
- 理解串行调用和并行调用的边界。

要做的代码：

- 先检索资料，再计算，再生成最终回答。
- 记录每个工具的输入、输出、耗时和错误。
- 展示一个工具失败导致整体流程变化的案例。

验收标准：

- 能解释为什么不是所有工具都应该并行。
- 能排查某一步工具输出错误导致最终回答错误的问题。

## 第二部分：提示词和输出契约

### 04：提示词工程

对应模块：

- `examples/agent/04_prompt_engineering`

目标：

- 理解 system prompt 在 Agent 中的职责。
- 理解角色、边界、任务、输出格式、禁止事项。
- 理解 prompt 版本管理。

要做的代码：

- 把 prompt 从代码中拆到独立文件。
- 支持 `PROMPT_VERSION`。
- 对比不同 prompt 对工具选择的影响。

验收标准：

- 能说明 prompt 改动为什么可能破坏工具调用。
- 能保留旧 prompt，并通过测试样例比较新旧版本效果。

### 05：结构化输出

未来模块：

- `examples/agent/05_structured_output`

目标：

- 理解为什么生产项目不能只依赖自然语言回答。
- 学习 JSON Schema / Pydantic 输出约束。
- 学习解析失败后的重试和降级。

要做的代码：

- 要求模型返回固定 JSON。
- 使用 Pydantic 校验模型输出。
- 输出不合法时返回可读错误或重试一次。

验收标准：

- 能解释“模型说得像 JSON”和“真的能被程序解析”的区别。
- 能处理缺字段、字段类型错误、非法枚举值。

## 第三部分：上下文工程

### 06：上下文工程

未来模块：

- `examples/agent/06_context_engineering`

目标：

- 理解模型每次请求到底应该看到什么。
- 管理 system prompt、用户问题、历史消息、RAG 结果、工具 observation。
- 控制上下文长度和优先级。

要做的代码：

- 构造 `build_context()`。
- 支持历史消息裁剪。
- 支持 RAG sources 注入。
- 支持工具 observation 注入。
- 展示“上下文太多反而干扰回答”的案例。

验收标准：

- 能解释为什么不能把所有历史都塞给模型。
- 能根据 token 预算选择保留哪些上下文。
- 能避免把无关资料放进上下文干扰模型。

### 07：短期状态管理

未来模块：

- `examples/agent/07_short_term_state`

目标：

- 区分一次请求状态和一次会话状态。
- 理解 Agent 当前任务进度如何保存。

要做的代码：

- 保存当前 Agent run。
- 保存 steps。
- 支持按 `run_id` 查询中间状态。
- 支持失败后查看已执行步骤。

验收标准：

- 能刷新页面后继续查看 Agent 执行记录。
- 能解释短期状态和聊天历史的区别。

## 第四部分：记忆工程

### 08：Agent 记忆基础

未来模块：

- `examples/agent/08_memory_basics`

目标：

- 理解聊天历史不等于记忆。
- 理解长期记忆是筛选、压缩、结构化后的信息。

要做的代码：

- 从对话中提取用户偏好。

- 后续请求自动检索相关 memory。

验收标准：

- 能说明哪些信息应该记，哪些不应该记。
- 能展示同一个用户的偏好在后续对话中被复用。

### 09：记忆治理

未来模块：

- `examples/agent/09_memory_governance`

目标：

- 学习记忆过期、删除、更新和隐私边界。

要做的代码：

- 支持查看记忆。
- 支持删除记忆。
- 支持记忆过期。
- 支持敏感信息拒绝写入。

验收标准：

- 用户能删除自己的记忆。

## 第五部分：工具工程

### 10：工具设计和权限

未来模块：

- `examples/agent/10_tool_permissions`

目标：

- 学习工具白名单、工具分组、用户权限。
- 理解读工具和写工具的风险差异。

要做的代码：

- 工具注册表。
- 工具权限检查。
- 不同 API Key 可调用不同工具。

验收标准：

- 普通用户不能调用管理员工具。
- 未授权工具调用会返回清晰错误。

### 11：危险操作和人工确认

未来模块：

- `examples/agent/11_human_confirmation`

目标：

- 学习删除、付款、发邮件、写数据库前的确认流程。

要做的代码：

- Agent 生成待确认操作。
- 用户确认后才真正执行。
- 记录确认人、确认时间和操作内容。

验收标准：

- 未确认时不会执行写操作。
- 确认记录可查询。

### 12：工具失败和恢复策略

未来模块：

- `examples/agent/12_tool_failure_recovery`

目标：

- 学习超时、重试、降级、失败解释。

要做的代码：

- 工具超时设置。
- 工具失败重试。
- 失败后让 Agent 选择继续、换工具或停止。

验收标准：

- 工具失败不会导致接口崩溃。
- 用户能看到失败原因和下一步建议。

## 第九部分：运行基座、可观测性和评测

### 19：Agent 运行基座工程

未来模块：

- `examples/agent/19_agent_harness`

目标：

- 搭建一个可批量运行、可复现、可回放、可接入评测的 Agent 运行基座。
- 这个能力也常被叫做 harness。

要做的代码：

- 测试样例集。
- 固定输入和期望行为。
- mock 模型。
- mock 工具。
- 批量运行 Agent。
- 保存每次运行的输入、输出、steps 和工具结果。
- 支持失败样例回放。

验收标准：

- 能一次运行多个 Agent case。
- 能复现某个失败 case。
- 能比较改 prompt 前后的运行结果。
- 后续评测和测试能复用这套运行入口。

### 20：Agent Trace 和日志

未来模块：

- `examples/agent/20_agent_observability`

目标：

- 让 Agent 每一步可追踪、可调试、可复盘。

要做的代码：

- run 日志。
- step 日志。
- tool call 日志。
- token、耗时、成本记录。

验收标准：

- 任意一次 Agent 调用都能查到完整 trace。
- 能定位是 prompt、检索、工具还是模型回答出了问题。

### 21：Agent 评测

未来模块：

- `examples/agent/21_agent_evals`

目标：

- 学习如何证明 Agent 改动真的变好。

要做的代码：

- 测试问题集。
- 期望工具调用。
- 期望 sources。
- 自动评分脚本。
- prompt 改动前后对比。

验收标准：

- 每次改 prompt 或工具后能跑 eval。
- 能看出准确率、工具选择正确率、引用正确率变化。

## 就业标准

学完这条 Agent 路线，最低应该能做到：

- 独立搭建 FastAPI AI 后端。
- 设计 Agent 循环。
- 设计安全工具调用。
- 构造高质量上下文。
- 做 RAG 检索和 sources 引用。
- 保存和治理 Agent 记忆。
- 搭建 Agent 运行基座。
- 记录 trace、日志、成本和错误。
- 用评测证明改动有效。
- 写测试保护关键链路。
- 用 Docker 部署完整项目。
- 拿出两个能演示的作品。

如果只学到 `01_tool_calling`，还只是 Agent 入门。

真正接近就业，要至少完成到完整项目阶段。
