# Agent 基础概念

## 普通聊天是什么

普通聊天接口的流程很短：

```text
用户输入 -> 模型回答
```

例如用户问：

```text
什么是 Agent？
```

普通聊天会直接生成一段解释。

这类接口适合：

- 概念解释。
- 文案生成。
- 简单问答。
- 不需要外部动作的问题。

## Agent 是什么

Agent 可以先理解成：

```text
会围绕目标选择动作的程序。
```

它的流程更像：

```text
用户目标 -> 判断下一步 -> 执行动作 -> 观察结果 -> 最终回答
```

重点是“动作”和“观察”。

如果用户说：

```text
帮我安排学习 Agent 的计划
```

普通聊天可能直接给一段建议。

Agent 更像是在处理一个目标：它会判断“这个目标需要拆计划”，然后调用一个计划生成动作，最后把结果返回。

## Agent 不等于大模型

大模型只是 Agent 的一个组成部分。

一个实际 Agent 通常包含：

- 模型：负责理解目标、判断下一步。
- 工具：负责查询资料、计算、写数据库、调用接口。
- 状态：记录已经做过什么。
- 循环：根据结果继续决定下一步。
- 限制：防止无限执行或执行危险动作。

所以 Agent 不是一个单独的模型名称，而是一种后端流程设计。

## Agent 不等于工具调用

工具调用是 Agent 的能力之一，但不是全部。

可以这样理解：

```text
工具调用：模型决定调用一个工具。
Agent：围绕目标，多次决定、执行、观察，直到完成或停止。
```

本模块只做一个最小 Agent 感知。

后面的模块会逐步学习：

- Tool Calling：怎么让模型选择工具。
- Agent Loop：怎么让 Agent 多轮执行。
- RAG Tool Agent：怎么把资料检索变成工具。
- Database Tool Agent：怎么让 Agent 操作结构化数据。

## 为什么要先学这个模块

如果一开始直接学 Tool Calling，容易误以为：

```text
Agent = 调一个函数
```

这不准确。

更准确的是：

```text
Agent = 围绕目标组织模型、工具、状态和控制流程。
```

这个前置模块的目的，就是先建立这张地图。
