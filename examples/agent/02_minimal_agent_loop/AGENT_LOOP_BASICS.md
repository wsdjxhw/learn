# 最小 Agent 循环基础知识

这个模块学习 Agent 最核心的一件事：循环。

普通聊天通常是：

```text
用户输入 -> 模型回答
```

工具调用模块通常是：

```text
用户输入 -> 模型决定是否调用工具 -> 后端执行工具 -> 模型整理最终回答
```

Agent Loop 多了一步“观察结果后继续决定”：

```text
用户目标
-> 模型决策
-> 工具调用
-> observation
-> 下一轮模型决策
-> 最终回答
```

## 为什么 Agent 需要循环

因为真实任务往往不是一步完成的。

例如用户说：

```text
帮我查深圳天气，再看报销制度，最后给一个出差提醒。
```

这句话里面至少包含两个动作：

- 查天气。
- 查报销制度。

如果只允许调用一次工具，Agent 只能完成其中一部分。循环让 Agent 能在拿到第一个工具结果后，继续判断下一步应该做什么。

## 什么是 observation

observation 是“工具执行后的观察结果”。

它通常包含：

- 工具名。
- 工具参数。
- 是否成功。
- 成功结果。
- 失败原因。

在代码里，observation 类似这样：

```json
{
  "tool_name": "get_weather",
  "arguments": {"city": "深圳"},
  "output": {
    "ok": true,
    "result": {
      "city": "深圳",
      "temperature": 30,
      "condition": "阵雨"
    }
  }
}
```

下一轮模型决策会读取 observation，再决定：

- 继续调用另一个工具。
- 工具失败后停止。
- 已经信息足够，生成最终回答。

## 真实模型在循环里做什么

真实模型不会直接执行 Python 函数。

在本模块里，DeepSeek 每一轮只负责做决策：

- 如果需要外部信息，返回 `tool_calls`。
- 如果 observation 已经足够，返回最终回答文本。

真正执行工具的是后端的 `run_tool()`。

这点很重要：Agent 不是“模型自己操作系统”，而是“模型提出动作，后端校验并执行动作，再把 observation 交回模型”。

## 为什么必须有 max_steps

Agent 不能无限循环。

如果没有最大步数，可能出现这些真实工程问题：

- 模型一直认为“还要再查一次”。
- 工具反复失败，模型仍然继续调用。
- 请求长时间不返回。
- 真实模型 API 成本不断增加。
- 服务被少量请求拖慢。

所以后端必须设置 `max_steps`。

本模块默认最多执行 3 轮，接口也限制最多 10 轮。

## 成功、失败、继续和停止

最小 Agent Loop 至少要能处理四种情况：

- 成功：工具返回结果，Agent 整理最终回答。
- 失败：工具返回错误，Agent 不让接口崩溃，而是解释失败原因。
- 继续：已经完成一步，但任务还没结束，于是进入下一轮。
- 停止：达到最终回答，或者触发最大步数保护。

这四种情况比“能调用工具”更重要，因为它们决定 Agent 在真实项目里是否可控。

## 本模块暂时不做什么

为了聚焦循环机制，本模块已经接入 DeepSeek 工具调用，但暂时不接数据库，也不做复杂多工具编排。

后续模块会继续加入：

- 多工具编排。
- prompt 工程。
- 结构化输出。
- 上下文管理。
- 短期状态保存。
- trace 和评测。
